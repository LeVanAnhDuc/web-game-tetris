## §1 The signature element — colour exists only inside the board

The playfield is the **only saturated region on screen**. Every chrome surface — HUD,
menus, Settings, tables, buttons — is achromatic. Two reasons, both structural:

- The 7 tetromino hues are fixed by convention and carry meaning. Any saturated chrome
  competes with them for the same channel.
- It is what makes `FR-26` (distinguish pieces without colour) implementable: with
  chrome achromatic, glyph or pattern overlays on pieces have the whole visual field.

Second manifestation: the HUD sits on the **board's own grid rhythm** — its numerals
align to a vertical rule continuing the playfield's right edge, so the HUD reads as an
extension of the board, not as a panel parked next to it.

**Single theme: dark only.** The 7 piece hues in §2 are tuned for a `#0E0F13` ground; a
light theme needs a second validated set of 7 and is not worth it at this scope.

### Measured contrast

Computed 2026-09-03 with the WCAG relative-luminance formula, not estimated. Rerun
before changing any value here.

| Foreground | on ground `#0E0F13` | on surface `#16181F` | on raised `#1E212B` |
| --- | --- | --- | --- |
| `--color-text` `#F4F5F7` | **17.56** | **16.25** | **14.72** |
| `--color-text-muted` `#A0A4AE` | **7.68** | **7.10** | **6.44** |
| `--color-text-disabled` `#6B7080` | 3.88 | 3.59 | 3.25 |
| `--color-danger-text` `#EB6E72` | **6.39** | **5.91** | **5.36** |
| `--color-danger` `#E5484D` | 4.89 | 4.53 | 4.10 |
| `--color-ring` `#FFFFFF` | **19.15** | **17.73** | **16.06** |

`--color-on-action` `#0E0F13` on the `#F4F5F7` fill: **17.56**.

Two entries are deliberately below 4.5 and must be used accordingly:

- **`--color-text-disabled` (3.25–3.88)** is for disabled controls only, which WCAG
  exempts. Never use it for text a user is expected to read.
- **`--color-danger` (4.10 on raised)** is **borders, fills and icons only** — a
  graphical object needing 3:1. Danger *text* uses `--color-danger-text`. This split
  exists because `#E5484D` failed 4.5:1 on the raised surface that every modal uses,
  which is exactly where "Reset to defaults?" lives.

**The focus ring is white**, 2px with a **2px offset**, and the offset is load-bearing,
not decoration. White on the white `--color-action` fill is **1.09** — invisible. The
offset draws the ring *outside* the element, so it is always measured against the
surface behind it (19.15 on ground), never against the element's own fill. A focus
style without the offset breaks on exactly one component: the primary button.

**`--color-danger` is for dialogs and Settings only. It never touches the board.**
The top-out warning is signalled by the board **frame** plus desaturation of locked
cells — never by hue, because red is already the Z piece.

### Playfield — the only colour

Canonical hue assignment (I cyan · J blue · L orange · O yellow · S green · T purple ·
Z red). **The hex values below are ours**, picked for contrast on `#0E0F13`; they are
not a transcription of anyone's official palette.

| Piece | Hex | CSS Variable |
| --- | --- | --- |
| I | `#3BC9DB` | `--piece-i` |
| J | `#4C6EF5` | `--piece-j` |
| L | `#FF922B` | `--piece-l` |
| O | `#FCC419` | `--piece-o` |
| S | `#51CF66` | `--piece-s` |
| T | `#CC5DE8` | `--piece-t` |
| Z | `#FF6B6B` | `--piece-z` |
| Ghost | `rgba(244,245,247,0.16)` | `--piece-ghost` |
| Grid line | `rgba(255,255,255,0.06)` | `--board-grid` |
| Board well | `#0A0B0E` | `--board-well` |

Measured against the well `#0A0B0E` — all seven clear 3:1 for graphical objects:
I **9.90** · J **4.55** · L **8.81** · O **12.23** · S **9.81** · T **5.90** · Z **7.09**.

**But piece-against-piece contrast is low and cannot be fixed by picking better hexes:**
T vs Z **1.20**, S vs O **1.25**, L vs O **1.39**, I vs J **2.18**. Seven hues on one
dark ground cannot all be mutually distinct — the hue assignment is fixed by convention,
so this is a property of Tetris, not of our palette. Two consequences, both binding:

- Adjacent locked cells of different pieces are separated by `--board-grid`, never by
  hue alone.
- This is the measured justification for `FR-26` / `NFR-A11Y-06`. The non-colour mode
  is not a nice-to-have: for a player who cannot separate T from Z, a 1.20 ratio means
  those two pieces are *the same piece*.

## §3 Typography — two families, both functional

```css
@import url("https://fonts.googleapis.com/css2?family=Space+Grotesk:wght@500;700&family=IBM+Plex+Mono:wght@400;600&display=swap");
```

| Role | Family | Fallback stack |
| --- | --- | --- |
| UI text, labels, buttons, headings | **Space Grotesk** 500/700 | `"Space Grotesk", "Segoe UI", system-ui, sans-serif` |
| Numerals, HUD, stats, keycaps, timers | **IBM Plex Mono** 400/600 | `"IBM Plex Mono", ui-monospace, "Cascadia Mono", monospace` |

The mono face is **not decorative**. The HUD rewrites score, level, lines and time
continuously, and proportional digits make those numbers jitter horizontally on every
update. Monospace gives tabular figures by construction. Any element whose digits
change while visible uses it, plus `font-variant-numeric: tabular-nums`.

Scale — `rem` on a 16px root:

| Token | Size / line-height | Usage |
| --- | --- | --- |
| `--text-hud-xl` | 2.5rem / 1.0 | primary HUD number (score) |
| `--text-hud` | 1.5rem / 1.1 | secondary HUD numbers |
| `--text-lg` | 1.25rem / 1.3 | screen title |
| `--text-base` | 1rem / 1.5 | body, labels, inputs (never below this for inputs) |
| `--text-sm` | 0.875rem / 1.45 | HUD captions, table meta |
| `--text-xs` | 0.75rem / 1.4 | **non-essential only** — never the sole carrier of meaning |

## §4 Spacing — kept from step 1

| Token | Value | Usage |
| --- | --- | --- |
| `--space-xs` | `4px` | tight gaps, cell gutters |
| `--space-sm` | `8px` | icon gaps, inline |
| `--space-md` | `16px` | standard padding |
| `--space-lg` | `24px` | section padding |
| `--space-xl` | `32px` | large gaps |
| `--space-2xl` | `48px` | section margins |
| `--space-3xl` | `64px` | screen padding at ≥1440 |

Density: **compact** for the HUD and stats tables, **comfortable** for Settings — a
keybind row is a hit target before it is a list item (§9, 44px).

Radius: `--radius-cell 2px` · `--radius-control 4px` · `--radius-panel 8px`. Sharp and
mechanical; a Tetris cell with an 8px radius stops reading as a grid cell.

## §5 Elevation — lightness, not shadow

Depth comes from surface lightness plus a 1px border. There is exactly **one** shadow
token, for modals, where a cast shadow does real separation work:

```css
--shadow-modal: 0 16px 48px rgba(0, 0, 0, 0.64);
```

| Level | Surface | Border |
| --- | --- | --- |
| flat | `--color-ground` | none |
| raised | `--color-surface` | `--color-border` |
| overlay | `--color-surface-raised` | `--color-border` + `--shadow-modal` |

## §6 Layout pattern — app shell, not a landing page

Three screens (`US-01` play · `US-02` settings · `US-03` scores), no marketing page.

**Mobile 375 is designed first**, then wider widths follow — never desktop shrunk down.

| Width | Board | HUD | Controls |
| --- | --- | --- | --- |
| 375 | centred, height-driven; cell size derived from available height | condensed row **above** the board | touch buttons in a fixed bottom band that **never overlaps the board** |
| 768 | centred | next/hold column right, stats left | touch band or keyboard |
| 1024 / 1440 | centred, fixed cell size | hold left · next right, both on the board's grid rhythm (§1) | keyboard; touch band hidden |

Board proportions are fixed by the rules: 10 columns × 20 visible rows, so the
playfield is always 1:2. The layout adapts around a 1:2 box; the box never distorts.

## §8 Motion — minimal tier

Game feel is the engine's job, not CSS (ADR-0003). CSS motion exists only to keep UI
state changes from being abrupt.

| What | Duration | Easing |
| --- | --- | --- |
| hover / focus / border | 150ms | `ease` |
| modal in-out, screen change | 200ms | `ease-out` |
| board effects (line clear, lock flash) | ≤120ms, **canvas-rendered** | engine-timed |

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    transition-duration: 1ms !important;
    animation: none !important;
  }
}
```

Under reduced motion, board effects collapse to an instant state change — the cleared
row disappears with no animation (`NFR-A11Y-05`). Never a layout-shifting hover.

## §9 Anti-patterns

- ❌ Any saturated colour on chrome — it collides with the piece hues (§1)
- ❌ `--color-danger` on the board — top-out is frame + desaturation, never red
- ❌ Proportional digits on a value that changes while visible (§3)
- ❌ Colour as the only carrier of meaning (`NFR-A11Y-06`, `FR-26`)
- ❌ Touch controls overlapping the playfield (§6)
- ❌ Emojis as icons — SVG only (Lucide), one set throughout
- ❌ Missing `cursor: pointer` on clickables · `cursor: pointer` on non-clickables
- ❌ Layout-shifting hovers (`transform: scale`/`translate` on hover)
- ❌ Text below 4.5:1, or an `<input>` under 1rem
- ❌ Invisible focus states
- ❌ Inconsistent styling · poor contrast

## §10 Pre-delivery checklist

- [ ] Text contrast ≥ 4.5:1; large text ≥ 3:1 (`NFR-A11Y-01`). The §2 table already
      clears this — a **new** colour has to be measured, not eyeballed. Only
      `--color-text-disabled` is exempt, and only on disabled controls
- [ ] Danger *text* uses `--color-danger-text`, never `--color-danger` (§2)
- [ ] Every focus style keeps `outline-offset` — without it the ring vanishes on
      `.btn-primary` (§2)
- [ ] Every action reachable by keyboard, focus always visible (`NFR-A11Y-02`)
- [ ] Touch targets ≥ 44×44px (`NFR-A11Y-03`)
- [ ] Inputs have linked labels; errors reachable by screen reader (`NFR-A11Y-04`)
- [ ] `prefers-reduced-motion` respected (`NFR-A11Y-05`)
- [ ] Pieces distinguishable with colour ignored (`NFR-A11Y-06`, `FR-26`)
- [ ] Responsive at 375 / 768 / 1024 / 1440, no horizontal scroll
- [ ] Board stays 1:2 at every width; touch band never overlaps it
- [ ] Changing numerals use tabular figures
- [ ] Icons are SVG from one set, no emoji
- [ ] Nothing hidden behind fixed bars
- [ ] No colour outside the playfield
